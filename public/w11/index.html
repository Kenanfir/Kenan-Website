3The three checks, cheapest first

Run range, then angle, then the ray, and stop at the first one that fails. Forty guards, nine in range, three in the cone: three raycasts instead of forty. The numbers in the picture are an example, not a measurement.

The names, as GDevelop 5.6 shows them

WhatWhere
Distance, objectsExpression Enemy.Distance(Player), or the condition Distance between two objects
Angle to the targetExpression Enemy.AngleToObject(Player), or AngleBetweenPositions(x1, y1, x2, y2)
Difference between anglesExpression AngleDifference(a, b). It returns -180 to 180
Inside the coneCondition Compare two numbers: abs(AngleDifference(Enemy.Angle(), Enemy.AngleToObject(Player))) <= 40
Line of sightCondition Raycast to position, in the Objects category. It tests objects or an object group, not a layer, and needs no Physics behaviour
Centre of an objectEnemy.CenterX() and Enemy.CenterY(). X() and Y() are the top-left corner by default

Three traps. Angles wrap: 350 and 10 are 20 apart, not 340, so always use AngleDifference. Y points down, so angle 90 looks down the screen. A sprite that flips never changes Angle(), so a platformer guard looks right forever. Set its Angle to 0 for facing right and 180 for facing left.

4Build it: the Vision behaviour

Two files, built with GDevelop's own library and tested against a test runtime. Importing them in the editor has not been tried, so if one will not import, tell Kenan in the clinic.

Vision.json   StateMachine.json

1. Import

  1. Open the Project Manager, then Extensions.
  2. Click Create or search for new extensions, then Import extension.
  3. Choose Vision.json, then StateMachine.json.

2. Attach

  1. Open your enemy object, then the Behaviors tab.
  2. Add a behavior: Vision. Then Add a behavior: StateMachine.
  3. On StateMachine, set State to patrol. The default is idle, and the Rules below have no idle row, so every move would be refused.
  4. Set Range 300, HalfAngle 40, Memory 3 on Vision. Different enemies can have different numbers.

3. Events

  1. Create two scene variables, HitX and HitY. The raycast writes the hit position into them, and only when it hits.
  2. Make an object group Obstacles with your walls. The guard and the player must not be in it.
  3. Event For each Enemy, action Enemy.Vision: Tick with TimeDelta(). Do this first every frame.
  4. Event For each Enemy, condition Enemy can see Player (range and angle only).
  5. Sub-event, condition Raycast to position: from Enemy.CenterX();Enemy.CenterY() to Player.CenterX();Player.CenterY(), against Obstacles, saved in HitX, HitY. A hit means blocked.
  6. Add an Else to that sub-event with the actions Saw target (Player) and Change state of Enemy to chase.
  7. Event For each Enemy, conditions has forgotten its target and is in state chase, action change state to search.

Do not tick Invert on the raycast. In 5.6 it means "return the farthest hit", not "nothing in the way". Why For each Enemy: in a plain event, Enemy.CenterX() in a condition reads only the first enemy. The Else item is in the add-event menu, and its exact position there has not been checked in the editor.

What the Can see condition does (JavaScript, optional) 
const b = eventsFunctionContext.getObjects("Object")[0]
  .getBehavior(eventsFunctionContext.getBehaviorName("Behavior"));
const me = eventsFunctionContext.getObjects("Object")[0];
const target = eventsFunctionContext.getObjects("target")[0];
if (!target) { eventsFunctionContext.returnValue = false; return; }

const dx = target.getCenterXInScene() - me.getCenterXInScene();
const dy = target.getCenterYInScene() - me.getCenterYInScene();

// 1. Range: the cheapest test. Most targets stop here.
if (Math.hypot(dx, dy) > b._getRange()) { eventsFunctionContext.returnValue = false; return; }

// 2. Angle: how far is the target from where I am facing? Wrap into -180..180.
const toTarget = Math.atan2(dy, dx) * 180 / Math.PI;
const off = ((toTarget - me.getAngle()) % 360 + 540) % 360 - 180;
eventsFunctionContext.returnValue = Math.abs(off) <= b._getHalfAngle();

// 3. Line of sight is NOT here. It is a raycast event in the scene.

Line of sight is deliberately not here. It is the raycast event in the scene.

Draw the cone while you build

You cannot debug perception you cannot see. Add a Shape painter object, tick Clear between frames or the cone smears, and use the Line action from the enemy's centre to Enemy.CenterX() + XFromAngleAndDistance(Enemy.Angle() - Enemy.Vision::PropertyHalfAngle(), Enemy.Vision::PropertyRange()), and the same with Y and +HalfAngle for the other edge.

5Memory, reaction and cues

  • Last known position. Saw target stores LastX and LastY. When it loses you, move to those numbers, not to the live player. Chasing the live position tracks you through walls.
  • Memory. Tick counts seconds since the last sighting. Forgot target is true after Memory seconds.
  • Reaction delay. Use an object timer: action Start (or reset) an object timer, condition Value of an object timer. A scene timer is shared by every enemy. A timer that was never started compares false.
  • Cue. A sound, an icon or a colour change the moment it changes state. If the player cannot tell they were spotted, the AI exists but the design does not.

6The enemy's rules

Paste this into the Rules property of StateMachine. It lets every state reach dead, so a guard that is shot while patrolling can still die.

patrol>suspicious,chase,dead;suspicious>chase,patrol,dead;chase>attack,search,dead;attack>chase,dead;search>chase,patrol,dead;dead>

Same idea as last week. Suspicious and search are the two states students skip, and without them an enemy is blind or all-knowing. Call ChangeState only when something changed: a refused move called every frame fills the console with warnings.

A clean four-state machine scores better in AFL-3 than a half-built behaviour tree. Use a tree when you need priority, for example flee if badly hurt, whatever else it was doing.

Roblox

I am making a Roblox game in Roblox Studio, Luau. I want a monster that notices the player by sight and by sound, remembers where it last saw them for 3 seconds, then gives up. Explain the approach using workspace:Raycast with RaycastParams and a Magnitude check for hearing. Name the API for every function you use, and list what could go wrong. Do not write code yet.

The bug it will find first: the flicker

Standing at the edge of the range makes one threshold flip every frame. Use two: enter chase at 300, leave at 340. Vision has one Range, so use its Set Range action: 340 when the guard starts chasing, 300 when it stops. The numbers in the picture come from a made-up wobble, not a measurement.

The trickWhat goes wrongThe fix

Optional: difficulty that adapts

Measure deaths, time to clear and hit rate. Adjust slowly, never announce it, and never touch the player's own damage, because that reads as the game cheating.
