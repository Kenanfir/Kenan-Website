2JavaScript cheat sheet for GDevelop

These calls were checked against GDevelop's own code. If your AI uses a function that is not in this list, check it before you trust it.

// runtimeScene : the scene the event is in
// objects      : the instances your conditions picked (add objects as parameters)

runtimeScene.getObjects("Enemy")                    // EVERY Enemy in the scene
obj.getX()  obj.getY()  obj.setX(n)  obj.setY(n)    // position
obj.deleteFromScene()                               // remove it (no argument)
runtimeScene.createObject("Enemy")                  // make a new one, returns it

runtimeScene.getVariables().get("Score").add(1)     // scene variable
obj.getVariables().get("hp").sub(10)                // object variable
variable.setNumber(n)   variable.getAsNumber()   variable.getAsString()

runtimeScene.getTimeManager().getElapsedTime()      // time since last frame, in MILLISECONDS
console.log("hello")                                // prints to the browser console

Three rules that catch most bugs

  1. Milliseconds. getElapsedTime() returns milliseconds. Divide by 1000 to get seconds.
  2. objects or getObjects(). objects holds only the instances your conditions picked. getObjects() returns every instance in the scene. Using getObjects() where you meant objects damages every enemy at once.
  3. deleteFromScene() takes no argument. Older examples online write deleteFromScene(runtimeScene). It still works, but you do not need the argument.

4Five checks before you keep code

  1. Does it run? Open the browser console in a preview. No red errors.
  2. Does it do what you asked? Watch it in the game, not just in the code.
  3. Do the calls exist? Compare against the cheat sheet.
  4. Does it hold up? Try zero enemies, a hundred enemies, pause and restart.
  5. Can you explain it? Ask your AI to explain it line by line, then keep it in a named, commented group in your event sheet.

5Maps and UI: ideas to try

Maps

  • Ask the AI for a grid of text, for example 30 wide and 12 tall, with a letter for each tile.
  • Your code reads each letter and creates the matching object at the right position. That is a good use of JavaScript.
  • Check it in the game: can you get from start to exit, is it too empty or too crowded, does it feel fair.

UI

  • Ask for the screens first: title, pause, game over, settings, and what goes on each.
  • Then ask for positions relative to the screen size, with a safe margin.
  • Then text size, contrast, and a short message when something changes.
  • Check it on a small screen, and hand it to someone and watch their first 30 seconds.

6Tester bots: ideas to try

A tester bot is a small program whose only job is to play your game and report what breaks. It runs in a separate test scene, and you remove it before you ship.

BotWhat it doesWhat it finds
MonkeyPresses random keys at random timesCrashes, falling out of the world, getting stuck
Human-likeReacts slowly, makes mistakes, holds keys for different lengthsWhether the difficulty feels fair for a person
Goal-seekerFollows simple rules: head for the exit, jump at gapsWhether a level can be finished at all
Monte CarloPlays hundreds of runs with random choices and counts the resultsWin rate, run length, which upgrade is always picked

What a bot can do in GDevelop

  • Press and release keys, and use the mouse, from a JavaScript code event.
  • Speed up time with the time scale, so many runs fit in a few minutes. Very high speed can break physics, so start low.
  • Write what happened to the console: where the player got stuck, fell out, or died.
  • Not tell you the game is fun. A person has to play it for that.

Which bot fits which game

GameGood botLook for
PlatformerMonkey, then goal-seekerFalling out of the world, a gap that cannot be jumped, getting stuck
Co-op horrorMonkeyDoors or puzzles that can be skipped, getting stuck in a room
Tower defenseMonte Carlo on wavesA tower or wave that is far too strong or too weak
Plinko DungeonMonte CarloHow often the boss dies, which upgrade is chosen every time

A tiny monkey bot, as an idea

// Idea sketch, test it in a preview before relying on it.
const input = runtimeScene.getGame().getInputManager();
const keys = [37, 38, 39, 40, 32];            // arrows and space

const k = keys[Math.floor(Math.random() * keys.length)];
input.onKeyPressed(k, 0);                     // press it
// ...a short random time later:
input.onKeyReleased(k, 0);                    // let go

runtimeScene.getTimeManager().setTimeScale(3);   // run faster
