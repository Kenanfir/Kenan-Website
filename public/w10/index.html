3The rules, as a table

Five booleans is 2 to the power 5, which is 32 combinations. Your game defines maybe six. One variable holding one word makes the impossible states impossible. Celeste's player is one state machine with 23 states, in a 5,471-line public Player.cs. Movement that feels that good is a list of states and the rules between them.

FromMay go to
idlerun, jump, hurt
runidle, jump, hurt
jumpfall, hurt
fallidle, hurt
hurtidle, dead
deadnothing

dead has no way out. That one line is the attack-while-dead bug, fixed for good. Draw yours on paper first. If an arrow you need is missing, that transition does not exist in the game either.

As one line of text, this is the Rules property:

idle>run,jump,hurt;run>idle,jump,hurt;jump>fall,hurt;fall>idle,hurt;hurt>idle,dead;dead>

Fast route: import the file

Download StateMachine.json

  1. Project Manager, Extensions, the plus button (Create or search for new extensions).
  2. Choose Import extension and pick StateMachine.json.
  3. Attach it to an object (step 6 below).

This file was built with GDevelop's own library and its code was tested against a test runtime. Importing it in the editor has not been tried in class, so if it will not import, use the steps below or ask in the clinic.

The steps

  1. Add an extension. Project Manager, Extensions, the plus button, then Create a new extension. Rename it StateMachine straight away (right-click, Rename).
  2. Add a behavior. Open the extension. In the left panel, Behaviors, Add a behavior. Name it StateMachine.
  3. Add properties. The four in the table. Choose the type for each. Right-click a property and choose Generate expression and action if scene events need it. Properties are private until you do.
  4. Add functions. Add a function and choose Action, Condition or Expression. Parameters 1 and 2 are always Object and Behavior. Add your own parameter after them, a text for next and name.
  5. Write the logic. In a JavaScript event, as in the next section. A condition must run the action Set condition return value if you use events. Forget it and the condition is always false, with no error.
  6. Attach it. Open an object, Behaviors tab, Add a behavior, pick StateMachine, and set its Rules. Do it on a second object type with different rules.
  7. Use it in events. Pick the action Change state of your object, and the condition is in state. Then delete the old boolean events from your scene. If you leave them, the logic runs twice.
// In your event sheet, using the behaviour on the Player:
Cond: Key "Space" was just pressed
      Player is in state run          <- the InState condition
Act:  Change state of Player to jump  <- the ChangeState action

Cond: Player collides with Enemy
Act:  Change state of Player to hurt

// If the player is dead, ChangeState to anything is refused and counted.
// No extra event is needed to stop a corpse from jumping.

Share it: open the extension, the gear icon (Open extension settings), Export extension, Export to a file. You get a plain .json file you can import into your next project.

5The JavaScript inside the behaviour

This is Week 9's JavaScript inside a part you built, and it covers the AFL-3 floor. There is no behavior or this variable inside the function, so you get the behaviour yourself with the first line. A property named State has _getState() and _setState(value), spelled exactly like the property.

// Every function starts with this line. It gets the StateMachine behaviour:
const b = eventsFunctionContext.getObjects("Object")[0]
  .getBehavior(eventsFunctionContext.getBehaviorName("Behavior"));

// ChangeState(next)  (action, parameter next is a text)
const next = eventsFunctionContext.getArgument("next");
const now = b._getState();
if (next === now) return;

// Rules look like "idle>run,jump;run>idle". Read them into a table.
const rules = {};
for (const part of b._getRules().split(";")) {
  const [from, to] = part.split(">");
  if (from) rules[from.trim()] = (to || "").split(",").map(s => s.trim()).filter(Boolean);
}

if ((rules[now] || []).includes(next)) {
  b._setPrevious(now);
  b._setState(next);
} else {
  b._setBlocked(b._getBlocked() + 1);          // a move the rules refuse
  console.warn("Blocked: " + now + " -> " + next);
}

// InState(name)  (condition, parameter name is a text)
eventsFunctionContext.returnValue = b._getState() === eventsFunctionContext.getArgument("name");

// CameFrom(name)  (condition)
eventsFunctionContext.returnValue = b._getPrevious() === eventsFunctionContext.getArgument("name");

// CurrentState  (expression that returns text)
eventsFunctionContext.returnValue = b._getState();

// BlockedCount  (expression that returns a number)
eventsFunctionContext.returnValue = b._getBlocked();

These were run against a test runtime, not in a full game. For example, from idle the moves run, jump, fall, idle, hurt, dead are all allowed, and then jump, run and idle are each refused and counted. If one fails in your project, read the console message and check the property spelling first.

The bug finder: the monkey bot plus BlockedCount (an idea, not run in a full game)

I have a GDevelop 5 StateMachine behaviour on my Player with an action ChangeState(next) and an expression BlockedCount.
Using the Week 9 tester bot idea (a random key pressed at random times, in an event group I can switch off, with its timer in scene variables), tell me:

- what a rising BlockedCount means, and what I should read in the console
- how to tell whether a blocked move is a bug in my events or a missing rule

Show BlockedCount in a text object. Each refused move prints in the console like Blocked: dead -> jump. A rising count means your events tried a move the rules forbid. Either an event is wrong or a rule is missing. A bot cannot tell you the game is fun. Remove the bot and the counter before you ship.

7Numbers as data: a structure variable

The test: to make every slime 20% tougher, how many places do you edit? If it is more than one, the number lives in the wrong place. Stardew Valley keeps its items and crops in data files, so mods change them without touching the code.

  1. Scene variables, Add a variable, type Structure, Add child. A child for each type, with health and speed inside.
  2. In events: EnemyStats.slime.health.
  3. Or read it in a JavaScript event. Adding a tenth enemy is then a data edit.
// Scene variable EnemyStats (Structure):
//   slime.health = 30   slime.speed = 80
//   boss.health  = 400  boss.speed  = 40
// JavaScript event. Object parameter: Enemy.

const stats = runtimeScene.getVariables().get("EnemyStats");

for (const enemy of objects) {            // every enemy the conditions picked
  const kind = enemy.getVariables().get("kind").getAsString();
  if (!stats.hasChild(kind)) continue;     // a typo is skipped, not created
  const s = stats.getChild(kind);
  enemy.getVariables().get("health").setNumber(s.getChild("health").getAsNumber());
  enemy.getVariables().get("speed").setNumber(s.getChild("speed").getAsNumber());
}

Run it in a sub-event of the event that creates the enemy, so objects holds the new enemy. getChild creates a child that is missing, so a typo makes an empty child instead of an error. hasChild checks without creating one. Scene variables reset when the scene starts.

8Saving, as an idea

  • Save little. Level reached, unlocks, high score, settings. Three numbers and a key is enough for most games here.
  • The actions: Save a value, Save a text, Load a value, Load a text, and the condition Existence of a group. Load puts the answer into a variable you name.
  • First launch has no save. A Load of a missing key leaves your variable as it was, so give it a default first.
  • A whole structure as text: the expression ToJSON(variable) to save it, and the action Convert JSON to a variable to load it.
  • Keep a version number so old saves can upgrade when the shape changes.
  • On the web the browser stores it, per browser. A private window or cleared site data looks like a lost save.

9Watch out for these

Watch outWhat goes wrongDo this
Behaviour not attachedIts actions are missing for that object, and getBehavior returns undefined.Object, Behaviors tab, Add a behavior. Check the name.
Forgot Set condition return valueThe condition is always false, or an expression returns 0.Set it in every condition and expression made with events.
Property seems missing in scene eventsProperties are private to the behaviour.Right-click it, Generate expression and action.
Rules text with a space or a typoMoves are refused that you meant to allow.No spaces around the > and commas. Names are case sensitive.
Default value against per-object valueYou change the default and old objects keep what they had.Set the Rules on each object. Check it once on a placed instance.
Cannot see your scene variables inside a functionExtension events only see the extension's own variables.Pass values as parameters, or read them in JavaScript.
Old boolean events left in the sceneThe logic runs twice and fights the rules.Delete them once the behaviour works.
getChild on a typoIt creates an empty child, so you get 0 and no error.Check with hasChild first.
Load of a missing keyYour variable keeps its old value.Give it a default, and test with Existence of a group.
State set from two placesOne frame cascades idle, run, jump, because events run top to bottom.Always go through ChangeState, so the table decides.
